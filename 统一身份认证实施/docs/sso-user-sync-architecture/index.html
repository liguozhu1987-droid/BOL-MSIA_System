SSO 用户同步架构：AD → 中央库 → Keycloak

实例 IRSCNYTFINEREPORT.ap.inalfa.local · 库 CN_AME · realm inalfa（Keycloak 25.0.6） · 脚本 C:\sso\scripts\ · 同步方向：单向

五张表：谁写、谁不许写

  • StgAdUser 只由 06:00 脚本 DELETE + BulkCopy 重灌，无唯一约束。
  • SSO_User 是事实来源：MERGE 写 AD 字段，KC 脚本只回写 kc_user_id/pwd_set。
  • UserMap 只服务应用侧身份解析，同步脚本不碰。
  • SyncLog 每轮一行（LOAD/MERGE/KC），逐人明细在日志文件。
  • PermLedger 是审计台账，改它不会自动改组。

除三处唯一约束外没有外键，一致性靠脚本。

这一跳为什么叫“对账”

先按 kc_user_id 取用户，取不到再按 username=login_name 查。查到就只比对 5 个字段（username / email / firstName / lastName / enabled），全一致时一个写请求都不发；有差异才 GET 整对象 → PUT 整对象。

查不到才 POST 建号，并在建号成功后立刻回写 kc_user_id，不等邀请邮件结果——否则邀请一失败就会留下“KC 有号、中央表没 ID”的洞。

停用：PUT enabled=false + POST /logout 踢会话；复职反向。不删 Keycloak 用户。

例外与边界（干活要记的）

  • source='MANUAL'：MERGE 的 UPDATE 与“名单消失→停用”都跳过它，admin 靠这个活着。
  • 排除名单 15 项只在 sync_sso_to_keycloak.ps1 维护；sync_ad_to_sso.ps1 默认空值不传参，夜间任务自动一致。
  • -SkipInvite：只建号不发信，新号在管理员代设密码前登不进。
  • duplicateEmailsAllowed 已开启：不再因邮箱重复 409，但“忘记密码”按邮箱定位会撞人不唯一——引导填 username。
  • 单人 4xx/5xx 只记 WARN 继续（H18）；401/403、HTTP 0、非 KC 异常仍立即中止。
  • KC 里改密码/姓名/邮箱不回流；中央表也不从 KC 拉数据。
路径按现场实际值；数据时刻以 CN_AME_SSO_SyncLog 最新一行为准。详细文字说明见 docs/sso-user-sync-architecture.md。
