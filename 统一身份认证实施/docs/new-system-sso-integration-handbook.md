# 统一身份认证接入规范（新系统）

> 性质：**规范文档**，不是部署记录。凡要接入本统一身份认证平台的新建或存量系统，均按本文执行。
> 强度：**必须** = 不满足不能接入；**应当** = 无正当理由不得偏离；**建议** = 推荐做法。
> 正文第 2–9 章为可判定要求，编号项共 **41 条"必须"**、2 条"应当"、3 条"建议"；第 10 章为验收标准，与技术栈无关的落地提示见附录 A。

## 1. 目的与适用范围

### 1.1 目的

规定接入统一身份认证的系统在设计、开发、部署三个环节必须满足的要求，使接入结果可验收、可运维、可替换。

### 1.2 适用范围

- 新建系统：立项/设计阶段即按本文约束技术选型与接口设计。
- 存量系统：改造后接入，同样按本文验收；改造前须明确哪些要求已满足、哪些需要改造。
- 不适用于纯后台批处理任务的身份调用（如服务账号取数），该场景另行申请。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 平台 | 统一身份认证平台（Keycloak），负责账号、组、认证、登出、令牌签发 |
| 接入系统 | 本文约束的对象，即使用平台登录的业务系统 |
| 准入组 | 平台侧 `app-<系统简称>` 组，决定谁有权进入该系统 |
| issuer | 平台分配给本系统使用的 realm 地址，是 discovery 的起点 |
| 网关 | 统一对外入口（IIS + ARR），终结 TLS 并反代到系统 |

## 2. 身份与协议要求

| 编号 | 强度 | 要求 | 判定 |
|---|---|---|---|
| R2.1 | 必须 | 使用 OIDC 授权码流程（`response_type=code`）；不得使用隐式流程或密码模式 | 授权请求含 `response_type=code`，无 `token`/`id_token` 直返 |
| R2.2 | 必须 | 通过 `issuer` 的 discovery 文档获取全部端点；不得硬编码 authorization / token / end_session / jwks 地址 | 平台换地址后只需改 issuer；代码中检索不到端点字面量 |
| R2.3 | 必须 | 回调时校验 `iss`、`aud`、`exp`、`nonce`、`state`；任一不通过必须拒绝登录 | 篡改任一值（含重放旧 state）均被拒绝并给出可读提示 |
| R2.4 | 必须 | 实现登出：调用 `end_session_endpoint`，携带 `post_logout_redirect_uri`，并同时清理本地会话 | 退出后本系统会话失效，平台会话结束，回到本系统登录页 |
| R2.5 | 必须 | 客户端类型为 confidential，使用平台分配的 `client_id`，并持有 `client_secret` | 平台侧该 client 为 confidential；换 token 请求带认证 |
| R2.6 | 必须 | `client_secret` 不得明文入库、写入代码仓库、写入日志或前端 | 全代码库与库表检索无命中；仅运行环境可见 |
| R2.7 | 建议 | 授权码流程附加 PKCE（S256） | 授权请求含 `code_challenge`，换 token 带 `code_verifier` |

## 3. 地址与主机名要求

| 编号 | 强度 | 要求 | 判定 |
|---|---|---|---|
| R3.1 | 必须 | `issuer` 与 `redirect_uri` 必须使用**同一主机名**（端口可不同）；`post_logout_redirect_uri` 也须在同一主机名下 | 四项配置回读，主机名逐字一致 |
| R3.2 | 必须 | 对外只暴露一个 https 入口（域名 + 端口），不得同时保留明文入口 | 该主机名/端口只存在一条对外绑定；http 访问不可用或 301 |
| R3.3 | 必须 | 系统必须能被网关通过 http 回环地址访问，且该回环端口不对外发布 | `http://127.0.0.1:<内部端口>/` 可访问；外部不可达 |
| R3.4 | 必须 | 系统不得自行对外提供 https 端口、不得自行持有服务端证书；TLS 由网关终结 | 系统无对外 https 监听，无证书部署依赖 |
| R3.5 | 必须 | 所有对外地址（issuer、redirect、页面链接、静态资源）必须使用域名，不得写 IP | 配置与页面源码检索无服务器 IP |

## 4. 反向代理契约

| 编号 | 强度 | 要求 | 判定 |
|---|---|---|---|
| R4.1 | 必须 | 正确消费 `X-Forwarded-Proto`、`X-Forwarded-Host`、`X-Forwarded-For`，按外部协议、主机、客户端 IP 还原请求上下文 | 应用侧请求上下文显示外部协议 https、外部 Host、真实客户端 IP |
| R4.2 | 必须 | 支持"外部 https、内部 http"的混合场景；不得因自身监听 http 而生成 http 绝对地址 | 经反代访问时，页面与接口不出现 http 绝对地址 |
| R4.3 | 必须 | 重定向地址、Cookie 域/协议、静态资源地址必须按外部协议与主机生成，不得产生 http 回跳或混合内容 | 302 的 `Location` 均为 https；浏览器无 Mixed Content 告警 |
| R4.4 | 应当 | 仅信任来自指定代理地址（如回环地址）的转发头，不得无条件信任任意来源 | 绕过网关直连应用伪造转发头，不改变应用判定的协议/主机 |
| R4.5 | 必须 | 审计日志必须记录真实客户端 IP（取可信 `X-Forwarded-For` 段），不得记录成网关地址 | 登录日志中 IP 为客户端地址，不是 `127.0.0.1` |

## 5. 必须提供的配置项

配置项**语义**必须齐全，命名不限；取值不得编译进程序。

| 编号 | 强度 | 配置语义 | 作用 | 取值规则 |
|---|---|---|---|---|
| R5.1 | 必须 | 平台地址（issuer） | discovery 起点 | `https://<统一域名>:<端口>/realms/<realm>`，无尾斜杠 |
| R5.2 | 必须 | `client_id` | 标识本系统 | 平台分配值，与平台侧逐字一致（含大小写） |
| R5.3 | 必须 | `client_secret` | 换 token 认证 | 由运行环境注入；轮换时先改配置再在平台重生成 |
| R5.4 | 必须 | `redirect_uri` | 登录回跳地址 | 绝对 https 地址，与 issuer 同主机名，精确到回调路径 |
| R5.5 | 必须 | `post_logout_redirect_uri` | 退出回跳地址 | 与 issuer 同主机名，通常为登录页，须在平台登记 |
| R5.6 | 必须 | `scopes` | 申请的身份信息范围 | 至少 `openid`；需要员工号/组时含对应 scope |
| R5.7 | 必须 | 准入组名 | 判定谁可进入 | `app-<系统简称>`，顶层组，与平台侧逐字一致 |
| R5.8 | 必须 | 本地账号登录开关 | 关闭后只留统一登录 | 接入验收前可开启，验收通过后置为关闭；默认关闭 |
| R5.9 | 必须 | 信任的代理地址 | 转发头采信范围 | 网关回环地址；不得填 `0.0.0.0` 或空 |
| R5.10 | 必须 | 配置外部注入 | 换环境不改包 | 支持环境变量或外部配置文件；改配置重启即生效 |

## 6. 用户与权限要求

| 编号 | 强度 | 要求 | 判定 |
|---|---|---|---|
| R6.1 | 必须 | 身份唯一键必须是员工号或平台下发的稳定 subject；不得用姓名、邮箱、手机号作主键 | 同一人换邮箱/改名后仍是同一账号 |
| R6.2 | 必须 | 首次登录必须能自动建档，且落**最低权限**（只读或"待分配"状态），不得直接获得业务权限 | 新用户首次登录后不能进行写操作或看不到敏感数据 |
| R6.3 | 必须 | 必须支持"同一人已有本地账号时绑定已有账号，而不是新建"的机制 | 老账号用户首次统一登录后，历史数据仍在其名下且无第二个账号 |
| R6.4 | 必须 | 准入组不满足时必须返回明确的 403 与可读提示（例如"尚未开通，请联系管理员加入 `app-<简称>`"），不得吞成 500、不得静默降级放行 | 非组成员登录后看到 403 提示页，日志记一行缺少的组名 |
| R6.5 | 必须 | 业务权限必须由本系统判定（本地角色/权限表），不得仅凭前端隐藏或直接采信令牌中的组 | 手工改前端或令牌不产生越权 |
| R6.6 | 必须 | 员工号缺失或无法映射时必须拒绝登录并记录可诊断日志，不得按姓名/邮箱猜测匹配 | 无员工号账号登录被拒，日志含可定位原因 |
| R6.7 | 必须 | 账号绑定关系必须持久化且可查询（映射表），不得只存在内存或日志中 | 可按员工号反查本地账号，重复登录不新建 |

## 7. 会话与安全要求

| 编号 | 强度 | 要求 | 判定 |
|---|---|---|---|
| R7.1 | 必须 | 会话 Cookie 必须 `Secure`、`HttpOnly`、`SameSite`（Lax 或 Strict） | 响应头 `Set-Cookie` 三属性齐全 |
| R7.2 | 必须 | 必须有 CSRF 防护，且在"外部 https / 内部 http"下仍能正确判定 | 登录后首次表单提交成功；跨站提交被拒 |
| R7.3 | 必须 | 必须有会话超时（空闲超时 + 绝对超时），超时后要求重新登录 | 到时后访问业务页跳登录页 |
| R7.4 | 必须 | 日志不得记录 `client_secret`、access/refresh/id token、用户密码 | 日志检索无敏感值；登录日志只记员工号与结果 |
| R7.5 | 应当 | 登录、登出、拒绝三类事件应有审计记录（不含敏感信息） | 可按员工号与时间检索到三类事件 |
| R7.6 | 建议 | HSTS 由网关统一启用，系统不单独下发 | `Strict-Transport-Security` 来自网关响应 |

## 8. 运维与可观测性要求

| 编号 | 强度 | 要求 | 判定 |
|---|---|---|---|
| R8.1 | 必须 | 提供健康检查端点，且不依赖外部系统（不查平台、不查外部库阻塞） | 平台不可用时该端点仍 200 |
| R8.2 | 必须 | 以 Windows 服务方式运行，失败自动重启 | 服务 `StartType=Automatic`，`Restart` 策略生效；杀进程后自动起 |
| R8.3 | 必须 | 启动失败必须输出可读日志（失败类别 + 关键配置名），不得静默退出 | 故意填错 secret 后启动，日志能指出是认证配置错误 |
| R8.4 | 必须 | 配置变更不得要求重新打包 | 改 issuer/secret/组名后重启生效，无需重新构建 |
| R8.5 | 建议 | 提供平台连通性自检（仅用于排障，不作存活判据） | 自检端点/日志可区分"平台不可达"与"应用故障" |

## 9. 交付物要求

| 编号 | 强度 | 要求 | 判定 |
|---|---|---|---|
| R9.1 | 必须 | 接入方必须提交以下三样，缺一不验收 | 三份文件齐备且内容与线上一致 |

| 交付物 | 必须包含 |
|---|---|
| 配置清单 | issuer、client_id、两项 redirect、scopes、准入组、本地登录开关、信任代理地址、secret 存放位置（只写位置不写值） |
| 联调记录 | 联调时间、测试账号（员工号）、每次登录结果、对应日志片段、问题与处置 |
| 验收证据 | 第 10 章每条的可复核证据（截图编号或日志行），含首次建档与配权后写操作 |

## 10. 验收标准

| # | 条目 | 判定方法 | 通过标准 |
|---|---|---|---|
| 1 | 登录回跳身份正确 | 用真实账号完成一次登录 | 显示员工号/用户名与账号一致，无空白、无他人数据 |
| 2 | 写操作可用 | 配权后做一次保存/提交并刷新 | 提交成功且刷新后数据仍在（验 R4.2/R7.2） |
| 3 | 退出无报错 | 点退出 | 回到本系统登录页，平台无 `Invalid redirect uri`（R2.4/R3.1） |
| 4 | 重启自恢复 | 重启服务器后不做人工干预 | 服务 `Running`、回环健康检查 200、外部 https 可登录（R8.1/R8.2） |
| 5 | 反代协议还原 | 查看重定向与页面资源 | `Location` 与资源地址均为 https，无混合内容（R4.1/R4.3） |
| 6 | 未开通提示明确 | 用不在准入组的账号登录 | 403 + 可读提示，非 500（R6.4） |
| 7 | 老账号绑定 | 用已有本地账号的用户登录 | 命中既有账号，不产生第二个账号（R6.3/R6.7） |
| 8 | 首次建档最低权限 | 用全新账号登录 | 自动建档且不能写业务数据（R6.2） |

## 11. 职责边界

| 事项 | 平台侧 | 系统侧 |
|---|---|---|
| 账号与密码 | 账号生命周期、密码策略、认证 | 不存密码、不提供本地改密入口（R5.8 关闭后） |
| 组与准入 | 建 `app-<简称>` 组、维护成员 | 校验 `groups` claim，拒绝非成员（R6.4） |
| 协议与令牌 | 签发/校验令牌、提供 discovery 与登出端点 | 走授权码流程、校验 claim、调登出（R2.1–R2.4） |
| 会话 | 平台会话 | 本系统会话、超时、CSRF（R7.1–R7.3） |
| 用户与权限 | 提供员工号、邮箱、组 | 建档、绑定、角色与业务鉴权（R6.1–R6.7） |
| 网关与证书 | 提供 issuer 域名与 client 参数 | 提供回环端口、配合网关反代（R3.2–R3.4） |

## 附录 A 技术栈落地提示

| 要求 | Python（waitress + Django） | Java（Spring Security OAuth2） | .NET（ASP.NET Core） |
|---|---|---|---|
| R2.2 / R5.1 | 用 `authlib` 或 `requests` 拉 `/.well-known/openid-configuration`，只配 issuer | `issuer-uri` 一项即可自动发现 | 配 `Authority`，`MetadataAddress` 自动推导 |
| R4.1 / R4.3 | waitress `trusted_proxy='127.0.0.1'`、`trusted_proxy_headers={'x-forwarded-proto'}`；Django `SECURE_PROXY_SSL_HEADER=('HTTP_X_FORWARDED_PROTO','https')` | `server.forward-headers-strategy=framework`，并在网关侧保留 Host | `UseForwardedHeaders` 并清空已知代理列表后加入网关地址 |
| R7.1 / R7.2 | `SESSION_COOKIE_SECURE=True`、`HttpOnly`、`SameSite=Lax`；Django CSRF 依赖上一条协议还原 | `CookieSameSite=Lax`、`Secure`；CSRF 基于还原后的 scheme | `Cookie.SecurePolicy=Always`、`SameSite=Lax`；防伪令牌随表单 |
| R7.4 | 日志过滤器屏蔽 `secret`/`token`/`password` 字段 | logback 脱敏过滤器 | `ILogger` 结构化字段白名单 |

## 附录 C 一页接入清单（操作顺序）

| # | 动作 | 通过判据 |
