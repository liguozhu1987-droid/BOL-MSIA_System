## 关键事件与决策

### 26 → 25.0.6 降级（根因：SQL Server 版本）
- Keycloak 26.x Liquibase 脚本执行 `CREATE INDEX ... WITH (OPTIMIZE_FOR_SEQUENTIAL_KEY = ON)`，该选项 **SQL Server 2019 才支持**；实测环境为 **SQL Server 2017 Express**（14.0.2042.3，Windows Server 2016）→ 26 建表必炸（`'OPTIMIZE_FOR_SEQUENTIAL_KEY' is not a recognized CREATE INDEX option`）。
- 决策：降级到 **Keycloak 25.0.6**（官方 zip 140MB，`https://github.com/keycloak/keycloak/releases/download/25.0.6/keycloak-25.0.6.zip`），25 的 Liquibase 无该选项，兼容 2017。
- 降级重装步骤已写入 runbook 第 10 章（停服 → 备份旧包 → 解压复用 conf/证书/JDBC 驱动 → 删库重建 → build → 管理员引导 → NSSM → 验证）。
- 长期隐患登记：**Express Edition 10GB 库上限**，建议 DBA 纳入容量监控。

### 管理员引导的版本差异（重要教训）
- **`kc.bat bootstrap-admin` 命令、`start --bootstrap-admin-username/--password` 参数、`KC_BOOTSTRAP_ADMIN_*` 变量都是 Keycloak 26 才有的**；25.0.6 里一律 `Unknown option`。
- **25.x 正确做法：首次启动（空库、master realm 不存在）前设 `KEYCLOAK_ADMIN` / `KEYCLOAK_ADMIN_PASSWORD` 环境变量，前台 `kc.bat start --optimized`**。创建的是永久管理员（26 才改成 120 分钟临时账号）。
- 用户侧已自行把 runbook §5 修正为 25.0.6 口径（5A 环境变量法 / 5B 本机 welcome page），并注明 26 特性不适用。
- 实际执行成功的命令序列（用户验证）：停服务 → 杀残留 java.exe（javaw.exe 是 Kettle 的，**不能杀**）→ `$env:JAVA_HOME/$env:KC_DB_PASSWORD/$env:KEYCLOAK_ADMIN/$env:KEYCLOAK_ADMIN_PASSWORD` → `.\kc.bat start --optimized` 前台跑完 Liquibase。
